prompt-triage now shows a status row under the prompt box. The row gives the session's cost, prompt count and how full the context window is, plus a button that offers Clear or Compact. This session reviewed that feature and fixed five problems. The button can no longer run a command twice, the prompt count no longer drops after a compaction, and the dialog runs a command only when you pick one of its options exactly. All 179 automated tests pass. The changes are pushed but not yet merged.

Decisions

  • Block the second press the moment the button is pressed. If the block started only once the dialog opened, two quick presses could both get through first. Rejected: setting the block inside the dialog code.
  • Count summarized prompts by adding them back. The count records how many prompts each compaction removed and adds them to what is left. Rejected: showing the highest count ever seen, which would freeze the number until new prompts passed the old peak.
  • Only an exact option runs a command. Clear and Compact both remove or rewrite the conversation, so a guess about what someone meant is too risky. Rejected: accepting either label with "(recommended)" attached.
  • Leave the README's "runs once the session is idle" claim as it is. A review said the button could run mid-turn. The Claude Code API docs say commands are queued until the session is idle, so the finding was dismissed.
  • Defer four smaller findings. They are listed under Open items. None of them can cause the wrong command to run.

Learnings

  • The compaction event fires before the compaction runs. Figures must be read after it finishes, not when it starts.
  • "Turns" in the Claude Code API means prompts still in the transcript, not every prompt ever sent. That is why the count dropped after a compaction.
  • On macOS, sed -i needs an empty '' argument. Edits used perl and Python instead.
  • Another commit landed on the branch mid-session (it moved the Clear threshold from 30% to 25%). Pull or re-read the branch before editing.

Open items

  • UnverifiedNothing has been tried in a real Claude Code session yet. Run the mod with claude --plugin-dir . and check two things: that compacting keeps the count, and that the button behaves well when its label switches between Clear and Compact.
  • DeferredThe dialog uses the context percentage from when the row was last drawn, which can be slightly out of date. Only the dialog text and its recommendation can be off, never which command runs.
  • DeferredEach redraw reads the prompt count and then the cost one after the other. Reading both at once would be a little faster.
  • DeferredThe row sits above the "Run in" picker in some layouts and below the refine pickers in others. This is a design decision.
  • DeferredThe 25% and 60% thresholds are fixed. Claude Code may auto-compact earlier than 60%, before the button ever says Compact. A code comment marks this.

Glossary

prompt-triage
This repo: a Claude Code mod that rates prompts and helps refine them before they are sent.
mod
A Claude Code plugin that changes Claude Code's own interface or behavior through hooks.
hook
A function the mod registers to run when Claude Code does something, such as drawing the screen or compacting.
band
The strip the mod draws above the prompt box.
status row
The bottom line of the band, showing cost, prompt count, context fill and the Clear or Compact button.
context window
How much of the conversation the model can hold at once. The row shows how full it is as a percentage.
/clear
Starts a fresh conversation and drops the old one.
/compact
Replaces the conversation with a summary so work can go on with more room.
precompute
A background pass that prepares a compaction before it happens.
turn
One prompt and the response to it.
