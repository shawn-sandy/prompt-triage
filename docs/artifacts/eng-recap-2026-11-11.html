Architecture and code paths

Everything is in hooks/register.ts. Read it in this order:

  1. ui.render reads $.session.turns() and adds compacted to get prompts. When prompts > 0 it also reads usage(). It builds the key:'status' Box. The key:'tidy' button is drawn only when percent >= CLEAR_AT (25), and its label is Compact from COMPACT_AT (60).
  2. onPress returns early if tidying is set. Otherwise it sets tidying = true and calls $.clock.after(0, tidy), because the dialog and the command outlast the press's 10 s budget. .finally clears the flag and redraws.
  3. tidy() calls $.ui.ask with [`${first} (recommended)`, other]. It runs $.command.run({command}) only when options.indexOf(answer) >= 0. The command is queued until the session is idle.
  4. session.compact skips agentId and trigger === 'precompute'. Otherwise it reads turns() before and after next(e), adds the drop to compacted, and then invalidates the band.
  5. session.end resets compacted, tracked and cleared, and redraws. turn.complete redraws on main-loop turns.

Decisions

  • The guard flag is set in onPress, not inside tidy(). It is set synchronously, so a second press made before the timer fires is dropped. Setting it inside tidy() would race two timers.
  • Dialog answers must match an options entry exactly. Before this, typing Clear (recommended) under a Compact recommendation ran /clear. Either command loses or rewrites the conversation, so any other text runs nothing.
  • The compacted-prompt count is an offset, not a running max. A max would freeze the count at the pre-compaction peak, while compacted += before - after keeps counting from where the session was.
  • precompute is skipped. It compacts nothing yet, so redrawing on it was wasted and counting on it would be wrong.
  • Tests assert figures, not wording. They match $0.42, 3 prompts and 30% context by regex, and check option order by prefix.
  • One review finding was rejected: "Clear or Compact runs mid-turn". The declaration of $.command.run says "queued and run once the session is idle", so the README's claim stands.

Tradeoffs and rejected options

  • DeferredReading the live percent in tidy(). A stale value changes only the dialog text and the recommendation, never which command runs.
  • DeferredRunning turns() and usage() together with Promise.all. The cost of reading them one after the other is small and hasn't been measured.
  • DeferredMoving the status row. It sits above Run in when the pickers are hidden and below the refine rows when they show. That is a design call.
  • DeferredReplacing the fixed CLEAR_AT/COMPACT_AT percents. The engine may auto-compact against a smaller window than the full one. The upgrade path is usage({ breakdown }), and a ponytail: comment marks it.

Learnings

  • session.compact fires before the compaction runs (the docs say "about to run"). Read figures only after await next(e).
  • $.session.turns() counts user turns still in the transcript, not prompts sent. That is why compaction made the row's count drop.
  • On macOS, sed -i without '' fails with invalid command code R. The session switched to perl -pi or Python for edits.
  • Prettier already flags hooks/register.ts on main, so formatting the touched files would have reformatted unrelated code. It was skipped.
  • Commit 52f930e (Clear threshold to 25%) landed from elsewhere mid-session. Re-read the branch before editing.

Review follow-ups and tech debt

  • The percent tidy() uses can be stale between draw and press.
  • turns() and usage() are read one after the other on every band render.
  • The status row moves relative to Run in as the pickers come and go.
  • The CLEAR_AT/COMPACT_AT constants ignore the engine's auto-compact window.
  • The decision-log turn delta in turn.complete drops a count that goes negative after a compaction instead of using compacted.
